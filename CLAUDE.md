# All Things Reptile — App

React PWA, live at app.allthingsreptile.com.au. Australian reptile keeping reference.
Owner: Rowan Peterson, Amphibian Pty Ltd. Hosted on Vercel; pushes to `main` deploy to production, every other branch gets a preview URL.

## Current work: structural refactor (branch `refactor/split-app`)

`src/App.js` (~4,280 lines) is being split into a proper structure. **No visual or behavioural change** until the refactor merges. The gate for merging: the branch preview renders identically to production and `npm run build` passes with no new warnings.

Target layout:

```
src/
  App.jsx                  routing shell only
  constants/colours.js     the C object
  data/                    species.js, categories.js, careGuides.js, glossary.js, states.js
  components/              shared UI (StatGrid, TempBar, WarnBox, FoodItem, HealthItem, ShopBtn, SectionLabel, LegalTab, InsectCard, LevelBadge, SplashScreen)
  screens/                 Browse, Care, Legal, Glossary, Identify, SearchResults
  screens/SpeciesScreen    one data-driven page for all species (D5; the 46 JSX pages are gone)

```

Order: constants and data → shared components → screens → species and care pages → App.jsx cleanup → React Router (real per-species URLs).

Work in small commits, one stage per pull request. Never push to `main` directly.

## Pre-launch gate (until launch; Rowan, 8 Nov 2026)

The live app (app.allthingsreptile.com.au, `main`) is **not publicly viewable until launch**: the information is changing fast.

- **`middleware.js`** (Vercel Routing Middleware, repo root) serves a static holding page ("All Things Reptile — coming 2027", HTTP 200, `X-Robots-Tag: noindex, nofollow`) to every page and asset request without a valid `atr_gate` cookie. The JS bundle and everything baked into it never reach a visitor without a pass. Only `/api/*`, `/robots.txt`, `/favicon.ico` and the invite bootstrap get through. Never add a route, asset or rewrite that serves app content around it.
- **Invite bootstrap:** tester links stay `/id?invite=<code>`. The middleware rewrites them to `/api/beta-check`, which checks the code against active `beta_testers`, sets the cookie and redirects to where the app will land them (Home, or their one section, e.g. `/id`) with no code in the URL (the code reaches localStorage through the 2-minute `atr_invite` cookie, for the existing `x-atr-beta` header).
- **Cookie:** `atr_gate`, HttpOnly, Secure, SameSite=Lax, 14 days, `{testerId, exp}` signed HMAC-SHA256 with `ATR_GATE_SECRET` (`lib/gate.js`, Web Crypto). The middleware never calls Supabase; the app's start-up check (`POST /api/beta-check`, which renews or clears the cookie) and every API call re-validate the tester, so deactivating a tester locks them out.
- **No `ATR_GATE_SECRET`** (or one under 32 characters): fail closed, everyone gets the holding page. Only `vercel dev` stays open; `npm start` runs no middleware.
- **`ATR_PUBLIC=true` is the launch switch**: the gate is off, robots are allowed (the middleware serves an allow-all `robots.txt`; `public/robots.txt` disallows everything while gated), and visitors with no invite get the public sections. Leave it unset until Rowan launches. `/admin` shows a banner with the server's gated/public state.
- **Per-tester sections.** Built sections a tester is given one by one: `id`, `species` (Browse at `/species` and species pages), `care` (care guides), `licensing`, `glossary`, `search`, `credits` (the `perTester` entries in `src/constants/sections.json`). `beta_testers.sections` (default `{id}`) holds each tester's; admins (`is_admin`) get all. New invites take `beta_settings.default_sections` (ID only by default), set in /admin → Testers alongside each tester's tick-boxes. "View care guide" on an ID result needs `species` or `care` (species pages count as care pages); otherwise the species is named with no link. The AI ID endpoints also need `id`. `/admin` stays admin-only on the server.
- **Tabs and sections (9 Nov 2026).** Five bottom tabs, fixed in code: **Home** (`/`), **Learn** (Species `/species`, Care guides, Licencing, Glossary, with a sub-nav; also `/search` and `/credits`), **ID** (`/id`), **Community** (`/community`: Sightings, Sighting ladders, Competitions, Venues) and **My Profile** (`/profile`: Shortlist, Can I keep it?, Shopping lists, Which reptile suits me?, My animals, Reminders, Account). Every section is defined once in `src/constants/sections.json` (tab, path, default title/blurb, `icon` key for the line SVGs in `src/components/Icon.jsx`, `built` or placeholder); the visibility rules are one CommonJS module, `src/constants/appLayout.js`, used by both the app and the server. `/admin → Sections` edits `app_sections` (status `live|soon|hidden`, audience `everyone|testers|admin`, order, one featured, title/blurb overrides) and `app_layout` (tab labels, Home block order: search, personal, featured, explore). Rules: hidden = admins only (with a Hidden badge); `soon` = Coming soon tile and page (a built section set to soon shows its placeholder instead of content, except to admins); placeholders can never be `live` and `id` can never be `everyone` (server refuses; D9). Placeholders need no per-tester grant: audience `testers` means every active tester. Built sections keep the per-tester grant before launch; after `ATR_PUBLIC=true`, audience `everyone` opens them to all. The full shell (Home + tabs) needs at least two built sections the visitor can open; with one, that screen alone and no tab bar, and no coming-soon tiles (ID-only testers still land on `/id`). A tab with no visible sections is hidden. The layout reaches the app through `/api/beta-check` (POST for testers; GET for the public, edge cached 30 s, and empty while gated), cached ~30 s per instance (`lib/appSections.js`); admin edits go through `api/admin-testers?scope=sections`. Home's personal block is a registry (`src/home/homeModules.jsx`: My animals, Reminders, Shopping list); while all are empty it shows one "Planning your first reptile?" card. Colours and sizes for the new screens live in `src/components/appUi.js` (roles mapped onto `theme.js` tokens).
- Vercel Hobby allows 12 functions; 9 are used. Extend an existing function (as `beta-check` does) before adding one.

## Content rules (non-negotiable)

- 46 species: 15 snakes, 9 lizards, 6 geckos, 6 monitors, 4 turtles, 6 frogs. Australian natives only — no Leopard Geckos or other exotics.
- Black-headed Monitor and Black-headed Python are different species; never let their IDs collide.
- Licence grids use each authority's own **licence names** as they appear on its website today (NSW Companion / Class 1 / Advanced licence; VIC Basic / Advanced licence; QLD Standard / Specialised / Advanced licence; SA Basic / Specialist permit; WA Pet keeper's licence; TAS Herpetofauna permit; ACT keeper licence, case by case; NT permit to keep). **Never** show species class codes (no NSW R-codes, QLD Class 1/2 species, VIC schedule numbers, WA categories). Every jurisdiction carries a "verify with your authority" disclaimer, and medium/low-confidence cells add "confirm with authority".
- Species-by-state availability was researched against every state's official keepable-species list in November 2026 (review page: ATR Licence Matrix artifact). Re-run that research before changing a grid by hand.
- TAS is always red/unavailable for non-TAS native species.
- Monitors need a 50–60°C basking surface (see D8 for the two exceptions) — feature it prominently on monitor pages.
- NSW no longer issues licences instantly; officially at least 8 weeks, often longer — warn clearly on the Licencing screen (the NSW record carries the warning). Don't quote 90 days; there's no official source for it.
- ACT: since 15 May 2026 no native reptiles are exempt. QLD, WA and ACT have no exempt reptiles; VIC, SA and NT have some.
- Licence facts in `data/states.js` were checked against official sources in November 2026; re-check before relying on them and update the date in each `verifyDisclaimer`.
- Wood Roaches are the primary feeder roach. **Dubia roaches are illegal in Australia** (not on the federal Live Import List; DCCEEW seizure June 2026) — never recommend them as a feeder; the Feeder Guide carries a warning instead. BSFL are sold as Calci-worms in Australia.
- Australian English throughout (colour, licence/license as noun/verb, enclosure, etc.).
- **Australian market first (Rowan, 11 Nov 2026).** All research and content starts from what is legal and actually available in Australia. Never recommend or mention a product, feeder, plant, supplement or animal that isn't sold or legal here (e.g. Dubia roaches, hornworms, US-only brands, fireflies); prefer Australian sources (AFD/ALA, museums, state departments, Australian vets, herp societies and suppliers) over overseas care sheets. **Exception:** things keepers here may already have but that are now illegal (Dubia roaches) keep a clear warning, so people know to stop keeping them; warn, never recommend.

## Supabase

Projects created from 30 Oct 2026 onward don't expose new `public` tables to the Data API automatically. Every migration that creates a table must include explicit `GRANT`s for the roles that need it, plus RLS enabled with policies.

**`atr` project** (ref `ledcvbyiqkygcdleucqo`, ap-southeast-2) holds the AI ID beta and the pre-launch gate: `beta_testers` (with `sections` and `is_admin`), `beta_settings`, `app_sections` and `app_layout` (the tabs' sections and Home, /admin → Sections; free-text `key`, rows for unknown keys are ignored; featured moves through `app_sections_set_featured()`, service_role only), `id_feedback`, `reference_photos`, `morphs`, `species_morphs`, `species_content` and `species_content_revisions` (species page content, D5), and the private `id-photos` and `reference-photos` buckets. **One exception:** the `species-photos` bucket is public (read-only public URLs for photos an admin has published to species pages); the `reference_photos` table itself stays closed. Feedback deletes (/admin → Feedback) remove the row and its `id-photos` file through the Storage API, since SQL can't delete storage objects. Only the server touches it — the Vercel functions in `api/` and the admin scripts in `scripts/`, using `SUPABASE_URL` + `SUPABASE_SECRET_KEY`. RLS is on with no client access; `anon`/`authenticated` have no grants; `service_role` has SELECT/INSERT/UPDATE/DELETE only. Never put the secret key in a `REACT_APP_` var or anything under `src/`. Migrations live in `supabase/migrations/`. Never touch the `amphibian-social` or `amphibian-studio` projects from ATR work.

**Morphs** live in Supabase (`morphs`, `species_morphs`, keyed by index slug) and Rowan edits them in /admin → Morphs; `lib/morphStore.js` serves them to the AI prompt, feedback and photo tags (about 60 s cache per instance), and `lib/morphs.js` is only the fallback seed. Delete morphs softly (`deleted_at`), never hard, and never change a morph's id.
